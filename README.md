# 돌봄자원 랩

> 도 소속 76개 군의 장기요양 공급격차를 진단하고, 같은 자원 총량을 서로 다른 기준으로 배치했을 때의 변화를 비교하는 공공데이터 분석 시뮬레이터

## 30초 요약

- **Problem:** 기관 수만으로 설명하기 어려운 76개 군의 서비스별 공급병목과 제한 자원의 배치 문제
- **Built:** 지역 병목 진단, What-if 변경, 자동배치 비교, 민감도·외부공급을 연결한 의사결정 지원 도구
- **Finding:** 방문간호기관 미관측 28곳과 배치전략별 수요 포괄·공급공백 완화의 trade-off 확인
- **Decision:** 하나의 최적순위 대신 정책목표에 맞는 전략과 현장검토 근거를 비교

## 핵심 결과

1. **방문간호의 최소서비스 기반이 가장 뚜렷한 과제였습니다.** 76개 군 중 방문간호기관이 자료에서 확인되지 않은 군은 28곳입니다. 기관 5개 대표 실행에서 기관 미관측 우선전략은 이 중 5곳의 공백을 줄였습니다.
2. **정책목표에 따라 유리한 전략이 달랐습니다.** 같은 방문간호기관 5개 조건에서 수요비례는 가장 많은 인정자(18,193명)를 포괄했고, 기관 미관측 우선은 연속형 공급격차를 가장 크게 줄였습니다(4.931).
3. **고령화만으로 부족지역을 정하지 않았습니다.** 고령화율·고령 1인세대 부담만으로 공급부족을 단정할 근거가 확인되지 않아 서비스별 공급격차, 수요압력, 접근공백을 함께 비교했습니다.

수치는 [`scenario_metrics.csv`](03_데이터/outputs/q4a_visit_nursing_mvp/scenario_metrics.csv)와 대시보드 공개 데이터에서 확인했습니다. 기관 “미확인”은 공개자료에서 확인되지 않았다는 뜻이며 실제 기관 부재와 같다고 단정하지 않습니다.

## 프로젝트 배경과 문제 정의

군 단위 실무자는 기관 수만으로 실제 제공역량을 판단하기 어렵고, 추가 자원이 주어져도 어디에 먼저 배치할지 비교할 공통 기준이 부족합니다. 이 프로젝트는 설치 확정안을 만드는 대신 공급공백과 현장검토 후보를 찾고, 효율·최소보장·취약성 등 정책목표가 다른 전략의 트레이드오프를 보여줍니다.

## 분석 대상 및 데이터

- 대상: 도 소속 농촌 군 76곳
- 서비스: 방문요양, 방문간호, 주야간보호
- 수요: 장기요양 인정자 기반 공통 잠재수요
- 공급: 서비스별 기관, 핵심인력, 주야간보호 정원
- 기준시점: 수요 2026년 5월, 공급·인구 2026년 6월
- 주요 출처: 행정안전부 주민등록인구, 국민건강보험공단 장기요양 공개자료, 공공데이터포털·KOSIS 공개자료

상세 계보와 공개 범위는 [데이터 안내](03_데이터/README.md)를 따릅니다.

## 분석 과정

```text
공공데이터 수집
→ 지역명·코드·서비스 분류 표준화 및 결합 검증
→ 인정자 1,000명당 서비스×자원 공급수준 생성
→ 기술·추론통계와 취약성·수요압력 진단
→ 목표 대비 부족지역과 기관 미관측지역 탐색
→ 동일 조건의 자원배치 전략 비교
→ 목표·수요·예산 민감도와 한계 검토
```

## 주요 분석적 의사결정

- 도 소속 76개 군을 주분석으로 두고 광역시 소속 군은 민감도 범위로 분리했습니다.
- 서비스 간 비교가 가능하도록 인정자 기반 공통 잠재수요를 사용하되 실제 서비스별 필요와 같다고 해석하지 않았습니다.
- 탐색 목표는 배치 전 공급수준 중앙값에서 고정해 배치 결과가 목표 자체를 바꾸지 않게 했습니다.
- 단위가 다른 기관·핵심인력·정원을 하나의 총량으로 합산하지 않았습니다.
- 하나의 최적전략을 선언하지 않고 수요비례·공급부족·기관 미관측·지역취약성 전략을 같은 조건에서 비교했습니다.
- “기관 미확인”과 실제 0을 구분하고, 비공개 셀은 공개값과 추정 하한·상한을 분리했습니다.
- 연관성 결과를 인과효과로 표현하지 않았으며 목표·수요·예산 조건에 대한 민감도를 함께 확인했습니다.
- Q1 통계검정은 취약성 지표를 각각 분석하고, 대시보드 복합점수는 지역 비교를 위한 탐색용 입력값으로 분리했습니다. 가중치는 공식 기준이 아니며 민감도 시나리오에서 결과 안정성을 확인합니다.

## 사용 기술

- 분석: Python, pandas, NumPy, SciPy, Matplotlib
- 대시보드: TypeScript, React, Next.js/vinext
- 품질검증: Python `unittest`, Node test runner, 정적 빌드

저장소의 의존성과 import를 기준으로 확인된 기술만 적었습니다.

## 담당 역할

저장소에서 확인되는 구현 범위는 공공데이터 수집·전처리, 지역·서비스 단위 통합과 검증, 지표·가설 설계, 기술·추론통계, 배치 시뮬레이션, 민감도 분석, 대시보드 구현과 결과 해석입니다.

## 대시보드 주요 기능

- 76개 군 핵심 현황과 검토 우선순위

- 자원 추가·감축·이전 및 직접·간접 영향 비교

## 로컬 실행

### 분석

```bash
python -m venv .venv
pip install -r requirements.txt
python "04_분석코드/check_preanalysis_readiness.py"
python "04_분석코드/analyze_ltci_resource_allocation.py"
python -m unittest discover -s "04_분석코드/simulation" -p "test_*.py" -v
```

일부 수집 스크립트는 공공데이터포털 또는 KOSIS 인증키가 필요합니다. 키는 저장소에 포함하지 않습니다.

### 대시보드

```bash
cd "06_대시보드"
npm install
npm run dev
```

정적 공개 빌드는 `npm run build:public`, 배포 빌드와 테스트는 `npm test`로 확인합니다.

## 분석 결과와 정책적 시사점

대표 실행은 “누가 가장 효율적인가”와 “어디의 최소 기반을 먼저 채울 것인가”가 서로 다른 결정임을 보여줍니다. 수요 대응에는 수요비례, 최소서비스 기반에는 기관 미관측 우선, 취약지역 우선검토에는 지역취약성 전략의 배치명단이 각각 유용합니다. 실제 선택은 설치 가능성, FTE, 대기, 이동시간과 정책 우선순위에 대한 현장검증을 거쳐야 합니다.

## 한계 및 후속 과제

- 공통 잠재수요는 서비스별 실제 필요를 직접 관측하지 않습니다.
- 신고 인력은 실제 FTE·운영시간·신규접수 여력을 뜻하지 않습니다.
- 같은 도 기반 외부공급은 실제 인접관계·도로 이동시간·기관 방문권역이 아닙니다.
- 시뮬레이션은 계산상 공급지표 변화이며 정책의 인과효과가 아닙니다.
- 비용·설치 가능성·기관 가동률을 포함한 현장자료 결합이 후속 과제입니다.
